Graph Colouring (m-colouring)

MediumbacktrackinggraphsO(m^V · V)NP-complete for m ≥ 3
GFG · M-Coloring Problem LeetCode 1042 LeetCode 785 (m = 2) AtCoder ABC199 D

Problem

Given an undirected graph G = (V, E) and m colours, assign a colour to every vertex such that no two adjacent vertices have the same colour.

Decision version: determine whether G can be coloured using at most m colours.

Representation: adjacency matrix A and vector<int> color(n, 0), where color[i] is the colour of vertex i and 0 means “not coloured yet”.

valid · m = 3 · [1, 2, 3, 1]

invalid · edge 0–1 has equal colours

What is the choice this time?

Hamiltonian cycle

Choice = which vertex should I visit next? The loop runs over vertices.

Graph colouring

Choice = which colour should I give the current vertex? The vertices are processed in a fixed order 0, 1, …, n−1; the loop runs over colours:

for (int c = 1; c <= m; c++)   // choice loop

What makes a colour a valid choice?

Suppose we want color[2] = 1. We must check: is any neighbour of vertex 2 already coloured 1? For every vertex j: if A[2][j] == 1 && color[j] == 1 then colour 1 is invalid.

That check is isSafe(v, c) — “can I assign colour c to vertex v without violating the colour constraint?” It is the isValid slot of the template. Uncoloured neighbours (color[j] = 0) never conflict.

Map it onto the template

Shared statecolor[0..n−1] (by reference); v = the vertex being coloured.
Base casev == n → every vertex has a safe colour → return TRUE.
Choicescolours c = 1 … m.
isValidisSafe(v, c): no u with A[v][u] == 1 && color[u] == c.
Changecolor[v] = c
Recurseif (solve(v + 1)) return true;
Revertcolor[v] = 0

Visualize it

Each tree node is one assignment vi=c, drawn in that colour. Crossed nodes are colours that IS-SAFE rejected — the red edge in the graph shows which neighbour caused it. Try K4 with m = 3 to watch the search exhaust every branch.

Dry run (from the notes) — m = 3

Start: color = [0, 0, 0, 0].
Vertex 0: neighbours 1 and 2 are uncoloured → colour 1 is safe → [1, 0, 0, 0].
Vertex 1: neighbours 0, 2, 3. Colour 1 is not valid (vertex 0 has it). Colour 2 is valid → [1, 2, 0, 0].
Vertex 2: neighbours 0 (1), 1 (2), 3 (0). Colours 1 and 2 clash → colour 3 → [1, 2, 3, 0].
Vertex 3: neighbours 1 (2), 2 (3). Colour 1 — no neighbour has it → [1, 2, 3, 1].
v == n → a valid colouring is found: [1, 2, 3, 1].

Algorithm (CLRS style)

In the handwritten notes these are GRAPH-COLOURING, COLORY and SAFE — same algorithm, different names.

Code

✓

Edge-list input (GFG): build an adjacency list and make isSafe scan only adj[v] — O(deg v) instead of O(n).

Complexity

TimeO(m^V · V)m choices for each of V vertices, O(V) isSafe per try (O(deg) with lists)
SpaceO(V)the color[] array and recursion depth V
Special case m = 2O(V + E)2-colourable ⇔ bipartite — a BFS/DFS check, no backtracking needed

Common mistakes

✗

Not resetting color[v] = 0. A stale colour on an uncoloured-in-theory vertex makes later isSafe checks reject valid colours.

!

Colours starting at 0. If 0 means “uncoloured”, real colours must be 1..m — otherwise isSafe treats every uncoloured neighbour as a conflict.

!

Disconnected graphs need no special handling here — vertices are coloured in index order, not by traversal.

Exercises

E1What is the chromatic number (minimum m) of the notes graph? Of K4? Of the Petersen graph?

Notes graph: 3 (vertices 0, 1, 2 form a triangle). K4: 4. Petersen: 3 (it has 5-cycles, so 2 is impossible). Find it by running m = 1, 2, 3, … until COLOR-UTIL succeeds.

E2How many valid 3-colourings does the notes graph have? Check with “All colourings”.

The triangle 0–1–2 can take the 3 colours in 3! = 6 ways; vertex 3 is adjacent to 1 and 2 so it must copy vertex 0’s colour. Total 6.

E3Sudoku as graph colouring: what are the vertices, edges and colours?

81 vertices (cells); an edge between two cells in the same row, column or 3×3 box; m = 9 colours (digits). Pre-filled cells are pre-coloured. The Sudoku solver is exactly this page’s algorithm with a different isSafe.

E4Symmetry: with m colours every solution appears m! times with colours renamed. How can you prune that?

Allow vertex v to use at most one new colour: c ≤ 1 + max(color[0..v−1]). Vertex 0 then only tries colour 1 — this alone cuts the search by up to m!.

E5Why might colouring the highest-degree vertices first reduce backtracking?

Highly constrained vertices fail fastest. Colouring them early detects dead ends near the root, where a pruned branch removes the largest subtree (“fail-first” heuristic, as in Welsh–Powell / DSatur).

E6Count the colourings of a graph with 3 colours for n ≤ 20 (AtCoder ABC199 D). Is plain backtracking fast enough?

3²⁰ ≈ 3.5·10⁹ is too many in the worst case. Colour vertices in DFS order within each connected component so every vertex after the first has an already-coloured neighbour (≤ 2 choices), and multiply the component counts: roughly 3·2¹⁹ per component — fast enough.
