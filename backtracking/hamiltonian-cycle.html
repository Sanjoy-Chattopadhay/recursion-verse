Hamiltonian Cycle

HardbacktrackinggraphsO(n!)NP-complete

Problem

Given an undirected graph G = (V, E) with n vertices (adjacency matrix A), find a cycle that

  1. visits every vertex exactly once, and
  2. returns to the starting vertex.

A Hamiltonian path relaxes rule 2: it must cover every vertex but need not come back. Vertices are 0-indexed on this page.

H-cycle exists. 0 → 1 → 3 → 4 → 2 → 0 (reverse direction is the same cycle).

H-cycle exists. 0 → 1 → 2 → 3 → 4 → 5 → 0.

Only an H-path. Vertex 2 is an articulation point: a cycle would have to pass through it twice. Path 0 → 1 → 3 → 2 → 4 → 5.

Designing the recursion

1 · What do we need to remember?

The vertices placed so far (path) and which vertices are already used (visited). Suppose path = [0, 1, 3]:

T0
T1
F2
T3
F4

Both are shared (by reference) and changed/undone as we go.

2 · What are the choices?

From the last vertex u = path[k−1] we may go to any vertex v that is not visited and adjacent to u. With path [0, 1, 3], v must be a neighbour of 3 that is still F in visited.

3 · Base case design

When path.size() == n every vertex is on the path — but that is only a Hamiltonian path. For a cycle we also need the edge from the last vertex back to the first:

if (path.size() == n)    return A[path.back()][path[0]] == 1;

4 · Why always start at vertex 0?

A cycle can be rotated: 0 → 1 → 3 → 4 → 2 → 0 and 2 → 0 → 1 → 3 → 4 → 2 are the same cycle. Every Hamiltonian cycle passes through vertex 0, so fixing it as the start loses nothing and divides the work by n.

Hamiltonian path instead? Drop the closing-edge check (if (k == n) return true;) and try every vertex as the start, because a path — unlike a cycle — cannot be rotated.

Complexity

TimeO(n!)at most (n−1)! orderings after fixing vertex 0, each extended with an O(n) neighbour scan
SpaceO(n)path, visited and a recursion depth of n
Faster exactO(2ⁿ · n²)bitmask DP (Held–Karp) — practical up to n ≈ 20

Deciding whether a Hamiltonian cycle exists is NP-complete; no polynomial algorithm is known. Backtracking with good pruning is the standard exact approach for small graphs.

Common mistakes

✗

Forgetting the closing edge. k == n alone only proves a Hamiltonian path.

✗

Not un-marking visited[v]. After one failed branch the vertex stays blocked forever and valid cycles are missed.

!

Counting cycles: starting from 0, each undirected cycle is found twice (clockwise and anticlockwise). Divide by 2 — or require path[1] < path[n−1].

Exercises

E1For K4 (complete graph on 4 vertices), how many Hamiltonian cycles does the find-all version print? How many distinct cycles are there?

Starting at 0, the remaining 3 vertices can be ordered in 3! = 6 ways, all valid. Each undirected cycle is counted twice, so there are 3 distinct cycles. In general (n−1)!/2.

E2Prove: a graph with an articulation point has no Hamiltonian cycle.

Removing the articulation point x splits the graph into at least two components C₁, C₂. A cycle through all vertices must go from C₁ to C₂ and back; every such crossing passes through x, so x would be visited at least twice — contradiction.

E3Add a pruning rule: if some unvisited vertex has fewer than 2 unvisited-or-endpoint neighbours, stop. Why is it safe?

In the final cycle every vertex has exactly two cycle-neighbours. If an unvisited vertex cannot get two neighbours any more, no completion of the current path can be a cycle — the whole subtree is hopeless, so prune it.

E4Count Hamiltonian paths that start at vertex 0 (AtCoder ABC054 C). What changes in the template?

Base case: k == n → count++ (no closing-edge check), and do not stop after the first success — use the find-all flavour.

E5A knight must visit every square of a 5×5 board exactly once. Map it to this page.

Vertices = squares, edges = knight moves. It is a Hamiltonian path problem on that graph. Choices: the 8 knight moves; isValid: inside the board and unvisited; ordering moves by Warnsdorff’s rule (fewest onward moves first) is a powerful pruning heuristic.

E6When would you switch from backtracking to bitmask DP?

When you need the count or the cheapest Hamiltonian path/cycle (an optimum → DP) and n ≤ 20: states (mask, last) number 2ⁿ·n. Backtracking stays simpler when you only need one cycle and good pruning finds it fast.
