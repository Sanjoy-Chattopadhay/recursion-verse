01 · Where it all starts

Choices + decisions → recursion

Whenever a problem says “pick one option, then pick again, then again…”, you are looking at a tree of choices. Recursion is simply the machine that walks that tree. The techniques differ in how they walk it:

Choices + Decisionspick, then pick again…
→
Recursionwalks the choice tree
→
Divide & Conquersplit · solve · combine — the laborious work
Dynamic Programming“optimal” (max / min / count) — answer at the root
Backtracking“all possible” — answer in the path
Backtracking = Pass by Reference + Controlled Recursion

Pass by reference

All calls share one state (a string, an array, a board). A call changes it before going deeper and reverts the change when it comes back — that “coming back and undoing” is the back-tracking.

Controlled recursion

We only recurse if a condition holds (isValid). Branches that can never lead to an answer are cut before we enter them. That is what keeps an exponential search usable.

02 · The key insight

Where does the answer live — leaf, root or path?

Recursion

At the leaf

Each call gets copies (input, output). When the input is used up, the leaf already holds the answer. Print it. Nothing to undo.

DP

At the root

A node can only answer after its sub-problems answer. Values flow upward and are combined; the root holds the final answer. Repeated sub-problems get cached.

Backtracking

In the path

One shared state records the choices made so far. The answer is the sequence of choices on the root → leaf path; we undo each choice on the way back up.

Switch between the three below. Watch the memory panel: copies per frame (leaf), a table of sub-answers (root), one shared path + used[] (path).

03 · Controlled recursion

Only recurse if the condition holds

You stand at P and want to reach home H, which is south-west of you. From any cell you could go N, E, S or W. But going north or east only moves you away from home — there is no point making those choices.

So instead of recursing on all four moves, we recurse only if the move can still lead to home. Same answers, far fewer calls. On a 3 × 3 grid:

Uncontrolled (N E S W)51 calls12 wandering paths, needs visited[]
Controlled (S W)19 calls6 shortest paths, no visited[] needed
✓

This if (isValid) check before the recursive call is exactly what the backtracking template calls pruning. Good pruning is the difference between “runs in 1 ms” and “never finishes”.

04 · Memory

Pass by value vs pass by reference

by value each call gets a copy

  • The callee works on its own copy; the caller’s data is never touched.
  • No undo needed — returning simply throws the copy away.
  • Cost: a copy per call → O(n) extra time and memory per frame.
  • Natural for the input/output method — answer at the leaf.

by reference all calls share one object

  • Every frame sees the same memory; a change made deep down is visible everywhere.
  • You must undo every change before trying the next sibling choice.
  • Cost: O(1) per change — no copies. This is why backtracking uses it.
  • The answer is the current contents of the shared state = the path.

Build every string of length 3 over {a, b} three ways. The third one forgets to undo — watch the shared string grow into garbage and the output turn red.

05 · Recognising the pattern

When should you reach for backtracking?

Choices + decisions

The answer is built step by step, and at every step you pick one option out of several.

“All possible …” → backtracking. “Max / min / count” → usually DP.

Asked to list / print / find all arrangements, subsets, paths? Backtrack. Asked only for an optimum or a count with overlapping sub-problems? Think DP first.

The number of choices is large — or varies

Choices can be “any unused letter”, “any safe colour”, “any unvisited neighbour” — a loop, not a fixed pair of calls.

Constraints are tiny: n ≤ 10 … 20

Small limits are the setter telling you an exponential (2ⁿ, n!, mⁿ) search is intended.

Don’t be greedy

If the locally best choice can be wrong later (e.g. duplicate digits in largest number in K swaps), you must try the alternatives — hit and trial, i.e. backtracking.

06 · Generalisation

The universal backtracking template

Every problem on this track is this code with the six coloured slots filled in. Learn the slots once; each new problem is just “what is my state, my choices, my validity check?”

base case / isSolution choices isValid (prune) make change (choose) recurse (explore) revert (un-choose)

Choose → explore → un-choose

1 · base case

Is the path complete?

Record a copy of the state (or return TRUE if one answer is enough).

2 · choices

What can I pick next?

Unused letters, positions to swap, unvisited vertices, colours 1..m.

3 · isValid

Can this choice still work?

Reject early — every rejected choice cuts off a whole subtree.

4 · choose

Modify shared state

push / swap / mark visited / assign colour.

5 · explore

Recurse one level deeper

The callee sees our change because the state is shared.

6 · un-choose

Undo exactly what you did

pop / swap back / unmark / reset colour — the backtrack.

Two flavours

Find all answers (permutations, all colourings): never stop early, record at every leaf.

Find one answer (a Hamiltonian cycle, one valid colouring): return TRUE as soon as a leaf succeeds.

10 · Check yourself

Exercises

E1How many nodes does the state-space tree of the permutations of “abcd” have (ignoring rejected choices)? How many leaves?

Level sizes are 1, 4, 4·3 = 12, 4·3·2 = 24, 24 → 65 nodes, of which 24 are leaves (4!). In general the tree has Σ n!/(n−k)! nodes for k = 0..n, which is about e·n!.

E2Why does the pass-by-value version never need an undo step? What does it pay instead?

Every call receives its own copy, so nothing the callee does is visible to the caller — returning discards the copy. The price is copying: O(length) time and memory at every call, versus O(1) for push/pop on a shared object.

E3In Python you write res.append(path) at the base case. All answers come out as []. Why?

You stored a reference to the same list object each time. Backtracking later pops everything, so every stored reference now points at an empty list. Store a snapshot: res.append(path[:]) or list(path). In Java: new ArrayList<>(path).

E4A problem asks for the minimum number of coins to make a sum ≤ 10⁴. Backtracking or DP?

DP. It asks for an optimum (not all combinations), sub-problems (“min coins for amount x”) repeat many times, and the constraint is far too large for an exponential search. The answer lives at the root: dp[sum].

E5In the controlled maze (only S and W), why don’t we need a visited[] array?

Each move strictly increases the row or strictly decreases the column, so the walk can never return to a cell it has already been on — cycles are impossible. Controlled choices removed both wasted calls and the need for extra state.

E6Turn the “find all” template into “find one” so that Hamiltonian cycle stops at the first cycle. Which lines change?

The procedure returns a boolean: the base case returns TRUE instead of recording, the recursive call becomes if BACKTRACK(state) return TRUE, and after the loop we return FALSE. See BACKTRACK-ONE above.

E7Fill the six slots for “print all subsets of an array without duplicates in the output, when the array has repeated values”.

Sort first. State: start index, current subset. Base: record the subset at every node. Choices: j from start to n−1. isValid: skip j if j > start and a[j] == a[j−1]. Change: push a[j]. Recurse: start = j + 1. Revert: pop. (LeetCode 90.)

E8Constraints say n ≤ 10. Estimate how many operations n! and 2ⁿ·n are. Would either pass in one second?

10! = 3,628,800 and 2¹⁰·10 ≈ 10⁴. Both pass comfortably (≈10⁸ simple operations per second). At n = 13, 13! ≈ 6·10⁹ — too slow without pruning.
