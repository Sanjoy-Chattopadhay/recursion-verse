Largest Number in K Swaps

Mediumbacktrackinggreedy trapO(n^k) worst case
GFG · Largest number in K swaps LeetCode 670 (k = 1) CF 915C · Permute Digits

Problem

Given a number as a string s and an integer k, perform at most k swaps of any two digits to make the number as large as possible. Return the largest number.

s = "1234567", k = 4 out 7654321 swap 1↔7, 2↔6, 3↔5
s = "3435335", k = 3 out 5543333
s = "4577", k = 2 out 7754 not 7745 (greedy)

Constraints (GFG): 1 ≤ |s| ≤ 30, 1 ≤ k ≤ 10.

Why not just be greedy?

A natural idea: for each position from the left, swap in the largest digit to its right. For 1234567, k = 4 it works — after the first swap you already want the largest number, so each swap is forced.

Now take 4577, k = 2. The largest digit, 7, appears twice:

Approach 1 — first 7 (index 2)

4577swap(0, 2)
7547swap(1, 3)
77457745

Approach 2 — last 7 (index 3)

4577swap(0, 3)
7574swap(1, 2)
77547754 ✓
i

Greedy is fine when the maximum digit is unique. With duplicates, which copy you move decides which smaller digit gets pushed where — and you cannot know that in advance. So you try every copy (hit and trial) and undo the ones that lose: backtracking.

Changeswap(s[idx], s[j]), then best = max(best, s).
Recursesolve(s, k − 1, idx + 1)
Revertswap(s[idx], s[j]) back.

The brute version maps even more directly: choices = every pair (i, j), isValid = s[j] > s[i]. It is correct but explores far more nodes — switch to it in the visualizer to compare.

Complexity

Brute timeO((n²)^k · n)n² pairs at each of k levels, O(n) to compare strings
Optimised timeO(n^k · n)worst case only when the max digit repeats a lot; usually close to O(n·k)
SpaceO(n)depth ≤ n (idx grows each call), s and best shared

Common mistakes

✗

Updating best only at the leaves. Using fewer than k swaps can be optimal (“at most k”). Compare after every swap.

✗

Spending a swap when s[idx] is already the maximum. Move to idx + 1 with the same k.

!

Trying only one copy of the max digit. That is the greedy bug — try all of them.

!

Passing s by value in C++. Correct, but copies the string on every call. Pass by reference and swap back.

Exercises

E1Find the answer for s = "129814999", k = 4 by hand. Where does greedy go wrong?

Answer: 999984211. The digit 9 appears four times; which 9 you move first decides where the displaced 1, 2 and 8 end up, so all copies must be tried.

E2Prove that greedy is optimal when all digits are distinct.

At the leftmost position that is not yet maximal, any optimal answer must place the unique maximum of the suffix there (otherwise it is smaller at that position, and higher positions dominate). With a unique maximum there is exactly one swap that achieves it, so the choice is forced — no alternatives to explore.

E3Modify the algorithm to find the smallest number with at most k swaps, with no leading zero.

Use min instead of max, and at idx = 0 restrict the candidate minimum to non-zero digits. Update best with min.

E4k = 1 only (LeetCode 670). Can you do it in O(n) without recursion?

Record the last index of each digit. Scan left to right; for position i, look for the largest digit d > s[i] (from 9 down) whose last index is > i. Swap with that last occurrence and stop.

E5Why does the optimised version iterate j over positions with s[j] == mx only, and is it still complete?

Any optimal solution puts the suffix maximum at the first non-maximal position; swapping in anything smaller can only produce a smaller number. So restricting to copies of mx prunes only branches that cannot win — the search stays complete.
