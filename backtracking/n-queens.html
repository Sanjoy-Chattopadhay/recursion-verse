n-Queen Problem

HardbacktrackingO(n!)
GFG · N-Queen Problem LeetCode 51 · N-Queens CSES 1624 · Chessboard and Queens

Problem

Place n queens on an n × n chessboard so that no two queens attack each other — no two share a row, a column or a diagonal. Print all such arrangements (or count them).

♛♛♛♛

4-queens: (2, 4, 1, 3)

♛♛♛♛

4-queens: (3, 1, 4, 2)

♛♛♛♛♛♛♛♛

8-queens: (1, 5, 8, 6, 3, 7, 2, 4) — one of 92

A solution is written as x[1..n], where x[i] is the column of the queen in row i.

Intuition

Each row must hold exactly one queen, so decide row by row: which column for the queen in row k? That shrinks the search from C(n², n) placements to at most nn, and since columns can't repeat, n!.

Place a queen in row k only if it is safe with all queens in rows 1..k−1, then recurse to row k + 1. If no column of row k is safe, we hit a dead end: go back (backtrack) to row k − 1 and move its queen to the next column.

Diagonal test: queens (i, x[i]) and (k, c) share a diagonal exactly when |x[i] − c| = |i − k|.

Shared statex[1..n] — the column chosen in each row.
Base casek > n → all rows filled, print x.
Choicescolumn c = 1..n for row k.
isValidPLACE(k, c): for all i < k, x[i] ≠ c and |x[i] − c| ≠ k − i.
Recursex[k] = c, then NQUEENS(k + 1).
Revertnothing to undo explicitly — the next choice overwrites x[k].

Algorithm (Horowitz–Sahni style)

✓

O(1) safety check: keep three boolean arrays — col[c], diag1[r + c], diag2[r − c + n]. Mark them when placing, unmark when backtracking (that is the explicit "revert").

Practice problems

P1How many solutions do n = 1 … 8 have?

1, 0, 0, 2, 10, 4, 40, 92. (n = 2 and 3 have none.)

P2Find the first 5-queens solution the algorithm prints.

(1, 3, 5, 2, 4) — row 1 col 1, row 2 col 3, row 3 col 5, row 4 col 2, row 5 col 4.

P3Why is it enough to try only columns 1..⌈n/2⌉ for row 1 when counting?

The board is symmetric: every solution with the first queen in column c has a mirror image with it in column n + 1 − c. Count the left half, double it, and handle the middle column once when n is odd.

P4Draw the first levels of the state-space tree for 4-queens. How many nodes does backtracking generate vs brute force?

Root → 4 children (row 1 columns) → each child only gets its safe columns, and so on. Counting the root and every safe placement, backtracking creates only 9 nodes before reaching (2, 4, 1, 3) (the 12 steps in the table above) — compared with 44 = 256 leaves for blind enumeration.

Drawbacks

✗

Exponential. Counting all solutions grows roughly like n!; n = 15 already takes noticeable time, n = 27 was a record computation.

!

O(n) safety check in the simple version — use the three boolean arrays (or bitmasks) for O(1).

!

Finding just one solution for large n is better done with a direct construction formula or local search (min-conflicts), not backtracking.
