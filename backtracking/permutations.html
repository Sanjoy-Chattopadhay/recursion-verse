All Possible Permutations of a String

Mediumbacktrackingpass by value vs referenceO(n · n!)
GFG · Distinct Permutations LeetCode 46 LeetCode 47 (duplicates) CSES · Creating Strings

Problem

Given a string s of length n, print every arrangement (permutation) of its characters. Follow-up: if s contains repeated characters, print each distinct arrangement only once.

Input : s = "abc" Output: abc acb bac bca cba cab Why : 3! = 6 arrangements
Input : s = "aab" Output: aab aba baa Why : 3! / 2! = 3 distinct arrangements

Constraints: 1 ≤ n ≤ 9 (n! grows fast: 9! = 362,880).

Why backtracking?

Choices + decisions

Position 0 can hold any of n letters, position 1 any of the remaining n−1, … ✓

“All possible”

We must list every arrangement, not the best one — so no DP. ✓

Variable number of choices

The number of candidates shrinks each level: n, n−1, …, 1 — a loop, not two fixed calls. ✓

Tiny constraints

n ≤ 9 — the output alone is n! strings, so exponential time is unavoidable. ✓

Map it onto the template

Approach B (swapping in place) filled into the six slots of the universal template:

Shared statethe string s (by reference) and idx = the position we are filling. Positions < idx are already fixed.
Base caseidx == n → every position is fixed → record s.
Choicesany letter still in the unfixed suffix: i = idx … n−1.
isValidalways valid for distinct letters; with duplicates, skip s[i] if that letter was already placed at idx in this loop.
Changeswap(s[idx], s[i]) — bring the chosen letter to position idx.
Recursepermute(s, idx + 1)
Revertswap(s[idx], s[i]) again — the shared string is back to how the loop found it.

Visualize it

Switch between the two approaches and watch the memory panel: approach A keeps a copy of ip/op in every frame, approach B has one array with two pointers. Try:

Two approaches, two memory models

A input / output — answer at the leaf

Keep an input ip of unused letters and an output op built so far. Move one letter from ip to op and recurse on the new copies. When ip is empty, op is a finished permutation.

abc | "" ├─ a → bc | a ─┬─ b → c | ab → abc │ └─ c → b | ac → acb ├─ b → ac | b ─┬─ a → c | ba → bac │ └─ c → a | bc → bca └─ c → ab | c ─┬─ a → b | ca → cab └─ b → a | cb → cba
  • No undo (pass by value).
  • Every call builds two new strings → O(n) extra work per call.
  • Output order is lexicographic when the input is sorted.

B swap in place — answer in the path

Fix positions left to right. At position idx, swap every candidate s[i] (i ≥ idx) into place, recurse, then swap back. The sequence of swaps on the root→leaf path creates the permutation.

i=0: abc ├─ swap a: abc ─┬─ swap b: abc │ └─ swap c: acb ├─ swap b: bac ─┬─ swap a: bac │ └─ swap c: bca └─ swap c: cba ─┬─ swap b: cba └─ swap a: cab
  • One shared array, O(1) per change — true backtracking.
  • Must swap back, or later branches start from a scrambled string.
  • Output order is not lexicographic (cba before cab).

Where do duplicates come from?

For "aab", placing the first a at position 0 and placing the second a at position 0 give identical subtrees — the swap tree prints aab twice, aba twice, baa twice.

Fix: keep a small set used local to each call. Before placing a letter at position idx, check whether that same letter has already been tried there. If yes, the whole subtree would be a duplicate — prune it.

!

The set must be per level (declared inside the function). A single global set would forbid the letter a at every position after its first use and you would lose valid permutations.

Complexity

TimeO(n · n!)n! leaves, each needs O(n) to copy / print; internal nodes ≈ (e − 1)·n!
Extra space (B)O(n)recursion depth n + one used-set per level (O(n²) worst case with sets)
Extra space (A)O(n²)each of the n live frames holds strings of length ≤ n

Common mistakes

✗

Forgetting the second swap. Later siblings then start from a scrambled string; you get repeated and missing permutations.

✗

Using one global “used” set for de-duplication. It must be declared inside the function so each position has its own.

!

Expecting sorted output from the swap method. For sorted output (LeetCode 47 / GFG) sort the input and use the used[] + path version, or sort the result.

!

Storing the shared object. In Java/Python always store a snapshot (new String(s), "".join(s)), never the mutable array itself.

Exercises

E1How many times is permute called for a string of 4 distinct letters (approach B)?

1 + 4 + 4·3 + 4·3·2 + 4·3·2·1 = 1 + 4 + 12 + 24 + 24 = 65 calls, of which 24 are leaves.

E2Without de-duplication, how many strings does the swap method print for “aabb”? How many are distinct?

It prints 4! = 24 strings; only 4!/(2!·2!) = 6 are distinct.

E3Write the used[] + path version (choose any unused index, append, recurse, pop). Which slot changes?

State: path, used[]. Choices: every index i. isValid: !used[i] (and for duplicates on a sorted array: skip if i > 0 && s[i] == s[i−1] && !used[i−1]). Change: used[i]=true; path.push(s[i]). Revert: path.pop(); used[i]=false. Output is lexicographic if s is sorted.

E4Print only the permutations of “abcd” in which no two vowels are adjacent. Where does the check go?

In isValid: before placing s[i] at idx, reject it if it is a vowel and s[idx−1] is a vowel. Pruning early is far cheaper than filtering finished strings.

E5Given n and k, return the k-th permutation of 1..n (LeetCode 60) without generating all of them.

Each first digit owns a block of (n−1)! permutations. Pick block ⌊(k−1)/(n−1)!⌋, remove that digit, set k ← (k−1) mod (n−1)! + 1 and repeat — O(n²), no backtracking needed. Knowing the tree’s shape lets you skip whole subtrees.

E6Beautiful Arrangement (LeetCode 526): count permutations where p[i] % i == 0 or i % p[i] == 0. Map it.

Fill position pos = 1..n. Choices: any unused number x. isValid: x % pos == 0 || pos % x == 0. Base: pos > n → count++. Pruning inside the loop keeps it fast for n ≤ 15.
