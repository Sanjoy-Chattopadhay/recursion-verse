Problem

A salesman must start at city 1, visit every other city exactly once and return to city 1. Given the cost matrix C[i][j] (cost of travelling i → j; ∞ on the diagonal), find the tour of minimum total cost.

Answer: tour 1 → 4 → 2 → 5 → 3 → 1 with cost 10 + 6 + 2 + 7 + 3 = 28.

Intuition

Brute force tries all (n − 1)! tours — 24 for 5 cities, but 87 billion for 15. Branch and bound builds tours city by city (the state-space tree) and needs a cheap lower bound on any tour that extends a partial path.

Reduced cost matrix: every city must be left exactly once, so each row contributes at least its minimum; every city must be entered once, so each column too. Subtract the minimum of every row, then of every column. The total subtracted is a lower bound on every tour, and the reduced matrix has a 0 in every row and column.

Child node (path extended by edge i → j): in the parent's reduced matrix A, set row i and column j to ∞ (i is left, j is entered) and A[j][1] = ∞ (no early return to the start). Reduce again, giving r. Then

ĉ(child) = ĉ(parent) + A[i][j] + r

Always expand the live node with the smallest ĉ (LC search). The first complete tour reached this way whose cost ≤ every other live node's bound is optimal.

✓

Optimal tour 1 → 4 → 2 → 5 → 3 → 1, cost 28. Check: C[1][4] + C[4][2] + C[2][5] + C[5][3] + C[3][1] = 10 + 6 + 2 + 7 + 3 = 28. Only 11 nodes were generated (root + 4 + 3 + 2 + 1) instead of the 65 nodes (24 complete tours) of the full tree.

Practice problems

P14 cities: C = [[∞, 10, 15, 20], [5, ∞, 9, 10], [6, 13, ∞, 12], [8, 8, 9, ∞]]. Find the root bound and the optimal tour.

Root reduction = 35. Optimal tour 1 → 2 → 4 → 3 → 1, cost 10 + 10 + 9 + 6 = 35 — here the root bound is already exact.

P2Why do we set A[j][1] = ∞ when the path reaches j?

Going j → 1 now would close the tour before all cities are visited. Blocking that entry keeps the bound honest.

P3Is the TSP solved faster by DP?

Held–Karp DP over subsets runs in Θ(n²·2ⁿ) time and Θ(n·2ⁿ) memory — guaranteed, unlike B&B, but only practical up to n ≈ 20. B&B with good bounds often solves larger instances in practice.

P4Compute the reduced cost of node 1 → 5 by hand.

From the root matrix, set row 1, column 5 and A[5][1] to ∞. Row 2's minimum becomes 2 and row 4's becomes 3 → r = 5. ĉ = 25 + A[1][5] + 5 = 25 + 1 + 5 = 31.

Drawbacks

✗

Still exponential in the worst case. TSP is NP-hard; a weak bound can force B&B to explore almost the whole tree.

✗

Memory hungry. Every live node stores an n × n matrix, and the priority queue can hold very many nodes.

!

Bound quality matters. Reduced matrices are simple; stronger bounds (1-trees, LP relaxations) prune far more but cost more per node.

!

For very large instances use approximation (2-approx via MST for metric TSP, Christofides 1.5) or heuristics (nearest neighbour, 2-opt).
