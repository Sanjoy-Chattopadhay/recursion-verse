What is dynamic programming?

Dynamic programming (DP) solves an optimisation problem by breaking it into sub-problems, solving each sub-problem only once, and storing its answer in a table so it is never recomputed.

Plain recursion on these problems recomputes the same sub-problems again and again (Fibonacci: fib(5) calls fib(3) twice, fib(2) three times …) and takes exponential time. DP turns that into polynomial time.

1 · Optimal substructure

An optimal solution is built from optimal solutions of sub-problems. (Shortest path A→C through B = shortest A→B + shortest B→C.)

2 · Overlapping sub-problems

The same sub-problems appear many times in the recursion tree. If they don't overlap, plain divide & conquer is enough.

Two ways to do DP

Top-down (memoisation)

Write the natural recursion, and before computing a state check a cache; after computing, store it.

def fib(n, memo={}):    if n <= 1: return n    if n not in memo:        memo[n] = fib(n-1) + fib(n-2)    return memo[n]

Bottom-up (tabulation)

Fill a table from the smallest sub-problems upward, in an order where every needed entry is already filled.

def fib(n):    f = [0, 1] + [0] * (n - 1)    for i in range(2, n + 1):        f[i] = f[i-1] + f[i-2]    return f[n]

The DP recipe

Define the state — what does T[i][j] mean in words? (best profit using the first i items with capacity j)
Write the recurrence — how is a state built from smaller states? (take item i or skip it)
Base cases — the smallest states you know directly (0 items → profit 0).
Order of filling — so every state you need is already computed.
Answer + reconstruction — which cell holds the answer, and how to trace back the choices.
