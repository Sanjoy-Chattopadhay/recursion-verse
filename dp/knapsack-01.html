Problem 01 · take it or leave it

0/1 Knapsack

MediumDPO(n·W)
GFG · 0 - 1 Knapsack AtCoder DP · D Knapsack 1 CSES 1158 · Book Shop

Problem

A bag can carry at most W units of weight. There are n items; item i has weight w[i] and profit p[i]. Each item is either taken whole (1) or left (0) — no fractions. Choose items with total weight ≤ W and maximum total profit.

W = 5 w = [2, 3, 4, 5] p = [3, 4, 5, 6] out 7 (items 1 and 2)
W = 50 w = [10, 20, 30] p = [60, 100, 120] out 220 (items 2 and 3)

Intuition

Why not greedy? In the second example, the best ratio is item 1 (6/unit), then item 2 (5), then item 3 (4). Greedy takes items 1 + 2 = 160 and has 20 units left that item 3 (weight 30) can't use. The best is items 2 + 3 = 220. Since items can't be cut, a locally good choice can waste space.

Look at the last item. In the best answer, item n is either not taken — then the answer is the best for items 1..n−1 with the same capacity — or taken — then it is p[n] plus the best for items 1..n−1 with capacity W − w[n]. Take whichever is larger. Those smaller questions repeat a lot, so we store them in a table.

State and recurrence

T[i][j] = maximum profit using only items 1..i with capacity j.

T[0][j] = 0, T[i][0] = 0 T[i][j] = T[i−1][j] if w[i] > j (can't take) T[i][j] = max( T[i−1][j], p[i] + T[i−1][j − w[i]] ) otherwise answer T[n][W]
✓

Space saving: row i only needs row i − 1. Use one array dp[0..W] and loop j from W down to w[i]: dp[j] = max(dp[j], p[i] + dp[j − w[i]]). Going downwards makes sure each item is used at most once. Space O(W).

T[2][5] = max(T[1][5], 4 + T[1][5 − 3]) = max(3, 4 + 3) = 7 — take item 2 together with item 1.
T[3][5] = max(T[2][5], 5 + T[2][1]) = max(7, 5) = 7 — item 3 is not worth it.
T[4][5] = max(T[3][5], 6 + T[3][0]) = max(7, 6) = 7.
Traceback from T[4][5] = 7: equals T[3][5] → skip 4; equals T[2][5] → skip 3; T[2][5] = 7 ≠ T[1][5] = 3 → take 2, j = 2; T[1][2] = 3 ≠ T[0][2] → take 1.

Answer: profit 7 with items {1, 2} (weight 5).

Practice problems

P1W = 7, w = [1, 3, 4, 5], p = [1, 4, 5, 7]. Fill the table and find the items.

Last row: 0, 1, 1, 4, 5, 7, 8, 9. Answer 9 with items {2, 3} (weights 3 + 4 = 7). Items {1, 4} give only 8.

P2W = 50, w = [10, 20, 30], p = [60, 100, 120] (CLRS). What do greedy and DP give?

Greedy by ratio: items 1 + 2 = 160. DP: 220 with items {2, 3}. (Fractional knapsack would give 240.)

P3W = 6, w = [2, 3, 3, 4], p = [1, 2, 5, 9].

10, items {1, 4} (weights 2 + 4 = 6). Items {2, 3} give only 7.

P4How many cells does the table have for n = 100, W = 109? What then?

1011 — too many. If profits are small, swap the roles: minWeight[i][profit] (AtCoder DP E, Knapsack 2). The algorithm is pseudo-polynomial: polynomial in the value W, not in the input size.

Drawbacks

✗

Pseudo-polynomial. O(n·W) depends on the value of W. W needs only log W bits to write, so for huge W the table is impossibly large. 0/1 knapsack is NP-complete.

!

Integer weights only. Real-valued weights can't index the table (scale them, or use branch and bound).

!

Memory: the full table costs O(n·W); the 1-D trick saves memory but loses the traceback.
