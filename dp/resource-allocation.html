Resource Allocation Problem

MediumDPmultistageO(m·N²)

Problem

We have N units of a resource (money, machines, workers) and m projects. Giving k units to project i earns profit Pi(k) (a table; Pi(0) = 0). Units are indivisible. Decide how many units xi each project gets, with x1 + … + xm = N, to maximise total profit Σ Pi(xi).

Units k01234
Project 1 — P₁(k)04678
Project 2 — P₂(k)02567
Project 3 — P₃(k)03469

N = 4 units. Answer: profit 12 with allocation (1, 2, 1).

Intuition

Think of it as a multistage decision: stage 1 decides project 1's share, stage 2 project 2's, and so on. After a decision, all that matters for the future is how many units are left — that number is the state.

Let fi(x) = the best profit obtainable from projects i, i+1, …, m with x units left. If project i gets k units, it earns Pi(k) and the rest optimally earn fi+1(x − k). Try every k, keep the best.

Greedy can fail: "give each unit to the project with the biggest next gain" sees project 2's first unit as worth only +2, although its second unit is worth +3 — returns are not concave. With ties broken towards project 1 it hands out 1 → P₁, 1 → P₃, 1 → P₁, 1 → P₂ for a profit of only 11. Trying all splits is necessary.

It is the same as finding a longest path in a multistage graph: vertices (stage i, units left x), an edge for every choice k with weight Pi(k).

Recurrence and algorithm

f(m+1, x) = 0 for every x f(i, x) = max over k = 0..x of P_i(k) + f(i+1, x − k) answer f(1, N) (store the best k in choice(i, x) to rebuild the allocation)

Practice problems

P1N = 5. P₁ = [0, 3, 7, 9, 12, 13], P₂ = [0, 5, 10, 11, 11, 11], P₃ = [0, 4, 6, 11, 12, 12]. Find the best allocation.

Maximum profit 21, reached by two allocations: (2, 2, 1) → 7 + 10 + 4, and (0, 2, 3) → 0 + 10 + 11. Optimal answers need not be unique.

P2How many allocations would brute force try for m projects and N units?

The number of ways to write N as an ordered sum of m non-negative integers: C(N + m − 1, m − 1). For N = 20, m = 10 that is 10 015 005 — DP needs only m·(N+1)²/2 ≈ 2 200 steps.

P3If the profit tables were concave (each extra unit gives less than the previous one), what simpler method works?

Greedy: hand out units one at a time to the project with the largest marginal gain. Concavity guarantees it is optimal; with non-concave tables (like P₃ above) it can fail.

Drawbacks

✗

Pseudo-polynomial. Running time grows with N², the value of the resource — large budgets need scaling or approximation.

!

Assumes independent projects. If profits interact (one project helps another), the state "units left" is no longer enough.

!

Needs the whole profit table for every project and every amount.
