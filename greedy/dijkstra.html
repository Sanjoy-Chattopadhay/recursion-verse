Problem 05 · closest vertex first

Dijkstra's Shortest Path Algorithm

Mediumgreedymin-heapO((V + E) log V)
GFG · Implementing Dijkstra LeetCode 743 · Network Delay Time CSES 1671 · Shortest Routes I

Problem

Given a weighted graph G = (V, E) with non-negative edge weights and a starting vertex s, find the shortest path from s to every other vertex (single-source shortest paths). A path can be a direct edge or go through other vertices; we must pick the one with the minimum total weight — a minimisation (optimisation) problem.

Intuition

Imagine pouring water in at the source; it spreads along the edges, and each vertex gets wet at the time equal to its shortest distance. Vertices get wet in order of distance.

Dijkstra simulates this. Among all vertices not yet finalised, the one with the smallest tentative distance cannot be improved any more — any other route to it would have to pass through a vertex that is already at least as far, and edges are never negative. So we finalise it greedily and use it to improve (relax) its neighbours.

Relaxation of edge (u, v): if going through u is shorter, i.e. d[u] + w(u, v) < d[v], update d[v] and remember u as v's predecessor.

i

Shortest paths are not necessarily unique — two different paths may have the same total weight. The distances are unique.

Solution technique

Set the distance of the start vertex to 0 and of every other vertex to ∞. Mark all vertices unvisited.
Select the unvisited vertex with the smallest distance.
Mark it as visited (its distance is now final).
Relax every edge from it to its neighbours.
Repeat until every vertex is visited (or the smallest distance left is ∞ — the rest are unreachable).

The code uses "lazy deletion": instead of DECREASE-KEY, push a new pair and skip outdated ones when they are popped. Same complexity, simpler code.

P3Give a small graph with one negative edge on which (textbook) Dijkstra gives a wrong answer.

A→B 2, A→C 3, C→B −2, B→D 1. Dijkstra finalises B = 2 (smallest) and relaxes B→D, so D = 3. Later C = 3 is picked and C→B would give B = 1, but B is already final and its edges are never relaxed again — D stays 3. True answers: B = 1, D = 2. Use Bellman–Ford.

P4How do you print the actual path, not just the distance?

Store the predecessor π[v] = u whenever an edge relaxes. Then follow π from the target back to the source and reverse.

Drawbacks

✗

No negative edges. A finalised vertex is never revisited, so a negative edge discovered later can give wrong answers (P3). Use Bellman–Ford, O(V·E), which also detects negative cycles.

!

Single source only. For all pairs you must run it V times, or use Floyd–Warshall O(V³).

!

Blind search. It explores in every direction equally; for one target on a map, A* with a good heuristic visits far fewer vertices.

!

Overkill for unweighted graphs. If every edge has weight 1, plain BFS gives the answer in O(V + E). With weights 0/1, use 0-1 BFS.
