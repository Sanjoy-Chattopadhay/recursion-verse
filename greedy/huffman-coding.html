Huffman Coding

Mediumgreedymin-heapO(n log n)
GFG · Huffman Encoding GFG · Minimum Cost of Ropes

Problem

Huffman coding is a lossless compression technique. Data is treated as a sequence of characters. Given each character's frequency, assign each character a binary code so that:

  • no code is a prefix of another (a prefix code, so decoding is unambiguous), and
  • the total number of bits Σ freq(c) × length(code(c)) is minimum.

Used for storing compressed files (ZIP / gzip's DEFLATE, JPEG, MP3) and sending data over the internet.

text CCDDEABBCCEADDBBACCB (20 characters) ASCII 20 × 8 = 160 bits out Huffman: 45 bits (+ 52-bit table = 97 bits stored)

Intuition

ASCII spends 8 bits on every character, common or rare. Huffman gives short codes to frequent characters and long codes to rare ones — like Morse code, where E is a single dot.

Codes come from a binary tree: characters are leaves, a left edge is 0, a right edge is 1, and a character's code is the path from the root. Depth = code length. So we want rare characters deep and frequent ones shallow.

The greedy step: the two least frequent characters should be the deepest — make them siblings by merging them into one node whose frequency is their sum. Then repeat as if that node were a single character.

i

Why it is optimal: in some optimal tree the two least frequent characters x, y are sibling leaves at the maximum depth (swapping them with the deepest leaves can only reduce the cost). Merging them into z with freq(z) = freq(x) + freq(y) leaves a smaller problem whose optimal tree extends to an optimal tree for the original (CLRS Lemmas 16.2 and 16.3).

Solution technique

Count the frequency of each character (frequency table).
Insert every character, as a leaf node, into a MIN-HEAP keyed by frequency.
Extract the two minimum nodes x and y; create a new node z with z.left = x, z.right = y, z.freq = x.freq + y.freq; insert z.
Repeat until the heap contains only one node — the root of the Huffman tree.
Label every left edge 0 and every right edge 1; read each leaf's code from root to leaf.

More worked examples

E2BANANA_BANDANA_BABANA_BANANA (28 characters)

Frequencies: A 12, N 7, B 5, _ 3, D 1.

Merges: D1 + _3 = 4 · 4 + B5 = 9 · N7 + 9 = 16 · A12 + 16 = 28.

Codes: A 0, N 10, B 111, D 1100, _ 1101.

Bits: 12·1 + 7·2 + 5·3 + 1·4 + 3·4 = 57 (vs 28 × 8 = 224). Table: 5 × 8 + 14 = 54. Total 111 bits.

E3a 45, b 13, c 12, d 16, e 9, f 5 (CLRS, 100 characters)

Merges: f5 + e9 = 14 · c12 + b13 = 25 · 14 + d16 = 30 · 25 + 30 = 55 · a45 + 55 = 100.

Codes: a 0, c 100, b 101, f 1100, e 1101, d 111.

Bits: 45 + 39 + 36 + 48 + 36 + 20 = 224 (vs 800). Table: 6 × 8 + 18 = 66. Total 290 bits.

E4m 4, n 7, o 8, p 3, q 1, r 4 (27 characters)

Merges: q1 + p3 = 4 · (qp)4 + m4 = 8 · r4 + n7 = 11 · 8 + o8 = 16 · 11 + 16 = 27.

Codes: r 00, n 01, q 1000, p 1001, m 101, o 11.

Bits: 8 + 14 + 4 + 12 + 12 + 16 = 66 (vs 216). Table: 6 × 8 + 17 = 65. Total 131 bits.

With different tie-breaking (merge r4 + m4 instead of (qp)4 + m4) you get a different tree whose code lengths add to 16 — the message is still 66 bits. The message size is always the same; the table size can differ slightly.

Practice problems

P1Frequencies a 10, e 15, i 12, o 3, u 4, s 13, t 1 (58 characters). Build the tree and find the number of bits.

Merges: t1 + o3 = 4 · 4 + u4 = 8 · 8 + a10 = 18 · i12 + s13 = 25 · e15 + 18 = 33 · 25 + 33 = 58.

Code lengths: i, s, e → 2 · a → 3 · u → 4 · o, t → 5. One labelling: i 00, s 01, e 10, a 111, u 1100, t 11010, o 11011.

11 → C, 11 → C, 00 → D, 00 → D, 10 → B. CCDDB.

P3If all 8 characters have the same frequency, what codes does Huffman produce?

A perfectly balanced tree: every code has length 3 — the same as a fixed-length code. Huffman helps only when frequencies are uneven.

P4Ropes of lengths 4, 3, 2, 6. Joining two ropes costs the sum of their lengths. Minimum total cost?

Exactly Huffman's merging: 2 + 3 = 5 · 4 + 5 = 9 · 6 + 9 = 15. Cost 5 + 9 + 15 = 29.

Drawbacks

✗

Two passes over the data. First count frequencies, then encode. Not suitable for streaming unless you use adaptive Huffman.

✗

The code table must be stored / sent. For short messages the table can cost more than it saves.

!

Whole bits per symbol. A character with probability 0.9 still needs at least 1 bit. Arithmetic coding gets closer to the entropy limit.

!

Ignores context. It looks at single-character frequencies only, not repeated words or patterns — that is why real compressors (DEFLATE) combine it with LZ77.

!

One bit error can corrupt everything after it, because codes have variable length.
