What is a greedy algorithm?

A greedy algorithm is a design strategy for optimisation problems (maximise or minimise something). At every step we choose the best immediate (local) option, hoping it leads to the best overall (global) solution.

Previous choices are never reconsidered — once a decision is made, it is final. That is what makes greedy fast, and also what makes it dangerous.

Recursion / Backtrackingtry every choiceexplore the whole tree, undo and retry
Dynamic Programmingtry every choice onceexplore all, but cache sub-answers
Greedytake one choicefollow a single root → leaf path, no going back

When is greedy correct?

A greedy algorithm gives the optimal answer when the problem has both of these properties:

1 · Greedy-choice property

There is always an optimal solution that contains the greedy choice. So making that choice first never hurts. (Usually proved with an exchange argument: take any optimal solution, swap in the greedy choice, show it is no worse.)

2 · Optimal substructure

After making the greedy choice, what remains is a smaller instance of the same problem, and an optimal answer to it combines with the choice to give an optimal answer overall.

!

DP also needs optimal substructure. The difference: greedy additionally needs the greedy-choice property, so it can skip exploring alternatives.

The greedy recipe

Find the key — what makes one choice "best"? (profit/weight ratio, earliest finish time, highest profit, smallest frequency, smallest distance)
Order by the key — sort the input, or keep it in a priority queue (min-heap / max-heap) when the key changes as you go.
Pick and check — take the next best item if it is feasible (fits in the bag, does not overlap, has a free slot …), otherwise skip it.
Never undo — move on. Stop when the input or the capacity is exhausted.

Typical cost: O(n log n) for the sort / heap + O(n) for the single pass.

When greedy fails

0/1 Knapsack

Capacity 50; items (w, p): (10, 60), (20, 100), (30, 120). Ratios 6, 5, 4.

Greedy by ratio takes items 1 and 2 → profit 160, 20 units wasted. Best is items 2 + 3 → 220. Items cannot be cut, so greedy fails. Use DP.

Coin change with coins {1, 3, 4}

Make 6 with the fewest coins. Greedy takes the largest coin first: 4 + 1 + 1 = 3 coins. Optimal: 3 + 3 = 2 coins.

Greedy works for "canonical" systems like {1, 2, 5, 10} but not in general. Use DP.

Dijkstra with negative edges

Once a vertex is finalised, Dijkstra never updates it again. A negative edge found later could have given a shorter path. Use Bellman–Ford.

Largest number in K swaps

With repeated digits, which copy you move matters (4577, k = 2 → 7754, not 7745). See the backtracking page.
