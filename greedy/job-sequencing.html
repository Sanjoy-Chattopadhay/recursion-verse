Problem 03 · highest profit, latest free slot

Job Sequencing with Deadlines

MediumgreedyO(n²) · O(n log n) with DSU
GFG · Job Sequencing Problem

Problem

Schedule jobs on a single processor. Every job takes exactly one unit of time and has a deadline d[i] and a profit (or penalty) p[i]. A job earns its profit only if it finishes by its deadline (equivalently: a job that misses its deadline pays its penalty). Choose which jobs to run and in which time slots so that the total profit is maximum — or the total penalty is minimum.

Job J1 J2 J3 J4 J5 J6 J7 Deadline 4 2 4 3 1 4 6 Penalty 70 60 50 40 30 20 10 out order J4 → J2 → J3 → J1 → J7, minimum penalty = 30 + 20 = 50

Maximising the profit of the jobs that are done and minimising the penalty of the jobs that are missed are the same problem: total − done = missed.

Intuition

Which job first? The most valuable one — losing it costs the most. So consider jobs in decreasing order of profit / penalty.

Where to put it? In the latest free slot on or before its deadline. Putting it as late as possible keeps the earlier slots free for jobs with tighter deadlines. If every slot up to the deadline is taken, the job cannot be done — discard it.

i

Time slots are unit intervals: slot t is the interval (t − 1, t]. A job with deadline d can use any slot 1 … d.

Solution technique

Sort all jobs in descending order of profit / penalty.
Create slots 1 … D (D = maximum deadline, or n if smaller), all empty.
For each job: scan from slot min(d, D) down to 1 and put the job in the first empty slot.
If no slot is free, discard the job (it misses its deadline).

P3Why do we put a job in the latest free slot and not the earliest?

Try deadlines [2, 1] with profits [100, 50]. Earliest-slot puts the 100-job in slot 1, and the 50-job (deadline 1) has nowhere to go → 100. Latest-slot puts the 100-job in slot 2, leaving slot 1 for the other job → 150.

P4Speed up the slot search with a Disjoint Set Union.

Let parent[t] point to the latest free slot ≤ t (slot 0 means "none"). find(d) gives the slot to use; after using slot t, set parent[t] = t − 1. With path compression every lookup is almost O(1), so the total becomes O(n log n) for the sort + O(n α(n)).

def find(t):    while parent[t] != t:        parent[t] = parent[parent[t]]        t = parent[t]    return t# for each job (by profit): t = find(min(d, D)); if t > 0: use slot t, parent[t] = t - 1

Drawbacks

✗

Only unit-time jobs. If jobs have different lengths, the problem becomes NP-hard in general (weighted scheduling with deadlines); greedy is not optimal.

✗

Only one machine. With several processors the slot idea must be extended.

!

Slow slot search. The simple version scans backwards for each job, O(n) per job → O(n²). Use a DSU for large inputs (n up to 10⁵ on GFG).

!

Ties. Jobs with equal profit can be taken in any order; the profit is the same but the sequence can differ.
