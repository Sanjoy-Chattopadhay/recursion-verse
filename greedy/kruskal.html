Problem 07 · cheapest edge, no cycle

Minimum Spanning Tree — Kruskal's Algorithm

Mediumgreedyunion-findO(E log E)
GFG · Minimum Spanning Tree CSES 1675 · Road Reparation

Problem

Same problem as Prim: given a connected, undirected, weighted graph, find a spanning tree (V − 1 edges, no cycle, every vertex connected) of minimum total weight.

Intuition

Prim grows one tree. Kruskal grows a forest: start with every vertex as its own tiny tree, then look at edges from cheapest to most expensive. Take an edge if it joins two different trees; skip it if both ends are already in the same tree (it would make a cycle).

Why safe? The cheapest edge joining two different trees is the lightest edge crossing the cut "this tree vs everything else" — by the cut property it belongs to some MST.

To test "same tree?" quickly we use a Disjoint Set Union (union-find): FIND(x) returns the representative of x's tree, UNION(x, y) merges two trees.

Solution technique

Make each vertex its own set (MAKE-SET).
Sort all edges in non-decreasing order of weight.
For each edge (u, v): if FIND(u) ≠ FIND(v), add the edge to the MST and UNION(u, v); otherwise discard it.
Stop after V − 1 edges are taken.

Practice problems

P1Graph: 0–3 6, 0–4 5, 1–2 9, 1–3 5, 1–5 1, 1–6 9, 2–6 7, 3–7 9, 4–6 4, 5–7 2, 6–7 7. Run Kruskal.

Take 1–5 (1), 5–7 (2), 4–6 (4), 0–4 (5), 1–3 (5), 0–3 (6), 2–6 (7). Skip 6–7, 1–2, 1–6, 3–7 (cycles).

MST weight = 30 — same as Prim from vertex 3.

P2Prim or Kruskal — which to use?

Kruskal is simple and fast for sparse graphs given as an edge list. Prim with an array is better for dense graphs (O(V²) without sorting E ≈ V² edges).

P3How do you detect that the graph is disconnected?

After processing all edges, fewer than V − 1 edges were taken.

P4Group n points into k clusters so the minimum distance between clusters is as large as possible.

Run Kruskal and stop when exactly k trees remain (after n − k unions). The next edge Kruskal would take is the answer.

Drawbacks

✗

Must sort every edge. On dense graphs (E ≈ V²) the sort costs O(V² log V) — slower than Prim's O(V²).

!

Needs a good union-find. Without path compression / union by rank, FIND can take O(V) and the algorithm becomes O(E·V).

!

Undirected only, like Prim.
