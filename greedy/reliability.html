Problem 09 · best gain per rupee

Optimal Reliability Allocation

Mediumgreedy heuristicexact: DPO(K·n)

Problem

A system is made of n stages connected in series; stage i uses device Di with cost c[i] and reliability r[i] (probability it works). The system works only if every stage works, so its reliability is the product of the stage reliabilities.

To make a stage more reliable we can put mi copies of Di in parallel — the stage fails only if all copies fail:

φi(mi) = 1 − (1 − r[i])mi    and    R = Π φi(mi)

Given a total budget C, choose m1, …, mn ≥ 1 with Σ c[i]·mi ≤ C to maximise R.

devices D1, D2, D3 cost 30, 15, 20 budget C = 105 r 0.9, 0.8, 0.5 out m = (1, 2, 2), R = 0.9 × 0.96 × 0.75 = 0.648

Intuition

A chain is only as strong as its weakest link. Every stage needs at least one device, so first buy one copy of each. With the money left, keep buying one more copy for the stage that gives the largest increase in system reliability per unit cost:

gain(i) = (R with one more Di − R now) / c[i]

Stop when no extra device fits in the remaining budget. Usually the weakest (lowest reliability) and cheapest stages get the extra copies — exactly what an engineer would do by hand.

!

This greedy is a heuristic: fast and usually optimal, but not always (see Drawbacks). Horowitz–Sahni solve the problem exactly with dynamic programming ("reliability design"), shown below for comparison.

Solution technique

Set m[i] = 1 for every stage; remaining budget B = C − Σ c[i] (if negative, no solution).
For every stage i with c[i] ≤ B, compute gain(i).
Add one copy to the stage with the largest gain; B = B − c[i].
Repeat until no stage fits in B.

Worked example — C = 105

One copy of each costs 30 + 15 + 20 = 65, so B = 40 and R = 0.9 × 0.8 × 0.5 = 0.36.

Exact method (dynamic programming)

Each stage needs at least one device, so stage i can have at most ui = ⌊(C − Σc + c[i]) / c[i]⌋ copies. Here u = (2, 3, 3). Let fi(x) = best reliability of stages 1..i using cost ≤ x:

fi(x) = max over 1 ≤ m ≤ ui of φi(m) · fi−1(x − c[i]·m),   f0(x) = 1.

Of the 2 × 3 × 3 = 18 combinations, checking those that fit the budget gives the best (1, 2, 2) with 0.648; the runner-up (1, 1, 3), cost 105, gives 0.9 × 0.8 × 0.875 = 0.63.

Practice problems

P1A stage has a device with r = 0.6. How many parallel copies make the stage at least 0.95 reliable?

Need 1 − 0.4m ≥ 0.95 → 0.4m ≤ 0.05. 0.43 = 0.064, 0.44 = 0.0256. m = 4.

P2c = (30, 15, 20), r = (0.5, 0.7, 0.9), C = 95. Run the greedy, then check the optimum.

Base cost 65, B = 30, R = 0.315. Gains: +D1 → 0.4725 (0.00525/unit), +D2 → 0.4095 (0.0063/unit), +D3 → 0.3465. Greedy adds D2 (B = 15), then D2 again → m = (1, 3, 1), R = 0.4379.

But m = (2, 1, 1), cost 95, gives R = 0.75 × 0.7 × 0.9 = 0.4725 — better. Greedy fails here: buying the cheap D2 left too little money for the expensive but most useful D1.

P3Why can't we simply use the profit/weight greedy of fractional knapsack?

Devices are indivisible (0/1-type decisions) and the objective is a product with diminishing returns — each extra copy of the same device adds less than the previous one.

Drawbacks

✗

Not always optimal (P2). Like 0/1 knapsack, indivisible purchases can leave budget unused. Use the DP for an exact answer.

!

Assumes independent failures. Parallel copies that share a power supply or a design bug fail together, and the formula overestimates reliability.

!

Only one constraint (cost). Real designs also limit weight, volume or power.
